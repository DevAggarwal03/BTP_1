## 2. Important decisions already made

These decisions were discussed and confirmed before implementation:

- Use exact statevector simulation, not shot-based simulation.
- Start with four qubits and also test eight qubits.
- Use angle encoding and an input-dependent data-reuploading circuit.
- Use a small trainable classical compression layer.
- Use density-matrix support prototypes and fidelity scores.
- Use a positive learnable fidelity-temperature parameter.
- Use 5-way/1-shot/15-query episodic evaluation.
- Keep QCHBA out of the main trainable model; it is a future separate ablation.
- Keep reusable code in Python modules and use notebooks only for exploration.
- Ask the user before implementation if a future decision is genuinely
  ambiguous and is not determined by the specification.

The exact statevector simulator is implemented directly with PyTorch complex
tensors. It is exact up to floating-point arithmetic. It must not be described
as quantum-hardware runtime or as evidence of quantum speedup.

## 3. Episode definition

The main task is 5-way/1-shot with 15 query examples per class:

```text
5 relation classes
1 support example per class       = 5 support examples
15 query examples per class        = 75 query examples
total per episode                  = 80 examples
```

Random guessing is 20% accuracy in a 5-way episode.

The main implementation uses independent train and validation relation sets:

- training: 64 relations, 700 examples per relation;
- validation: 16 relations, 700 examples per relation;
- train/validation relation overlap: none.

The cached source files are:

```text
/Users/devaggarwal/BTP/BTP_combined/BTP_Quantum_few_rel/data/train_embeddings.npz
/Users/devaggarwal/BTP/BTP_combined/BTP_Quantum_few_rel/data/val_embeddings.npz
```

The new loader reads these files by default. Each file contains `embeddings`
with shape `[number_of_examples, 384]` and `labels` containing relation IDs.

## 4. Active architecture

The active pipeline is:

```text
FewRel text
  -> frozen 384-dimensional Sentence-BERT embedding
  -> LayerNorm
  -> Linear(384, 64)
  -> GELU
  -> Linear(64, n_qubits)
  -> pi * tanh angle bounding
  -> exact statevector circuit
  -> density-matrix support prototypes
  -> fidelity scores
  -> positive learnable beta
  -> cross-entropy loss on query labels
```

### Text representation

The cached embeddings were generated by the old data-preparation script using
`all-MiniLM-L6-v2`. That script inserts `[H] ... [/H]` markers around the head
entity and `[T] ... [/T]` markers around the tail entity before encoding.

`qpn_hybrid/embeddings.py` also contains a lazy frozen Sentence-BERT helper,
but the current experiments use the cached `.npz` embeddings and do not reload
the language model every run.

### Classical compression

`qpn_hybrid/compression.py` contains `CompressionNetwork`:

- `LayerNorm(384)`;
- default nonlinear path `Linear(384, 64) -> GELU -> Linear(64, n_qubits)`;
- final output `pi * tanh(raw_angles)` so angles remain bounded.

The current main model uses the nonlinear path and 8 output angles for the
8-qubit experiments.

### Exact quantum encoder

`qpn_hybrid/quantum_encoder.py` contains
`DataReuploadingQuantumEncoder`:

- starts each example in `|0...0>`;
- applies input-dependent RY rotations to every qubit;
- applies trainable RY and RZ rotations;
- applies a circular CNOT entanglement chain;
- repeats this sequence twice by default;
- returns a normalized complex statevector of length `2**n_qubits`.

The input is reintroduced in every repetition. This avoids the earlier
problem where all examples differed only before one common final unitary,
which made global fidelity insensitive to trainable circuit parameters.

### Prototype and objective

`qpn_hybrid/prototypes.py` builds one density matrix per class by averaging
the support state projectors. A query score is:

```text
fidelity(query, prototype) = <query | density_matrix | query>
```

`qpn_hybrid/model.py` multiplies these scores by a positive learnable `beta`
implemented with `softplus`, then uses cross-entropy over query labels.

Training and evaluation use the same prototype and fidelity calculation.

## 7. Completed results

All results below use the current exact statevector model unless explicitly
labelled as a classical baseline.

### Main model, 600 training and 600 validation episodes

The seeded single-run checkpoints were produced after fixing the launcher so
the seed is set before model construction:

| Model | Accuracy | Weighted F1 |
|---|---:|---:|
| 4 qubits, seed 7 | 50.80% | 48.24% |
| 8 qubits, seed 7 | 59.20% | 56.24% |

### Main model, three seeds: 7, 17, 27

| Model | Mean accuracy | Accuracy standard deviation | Mean weighted F1 |
|---|---:|---:|---:|
| 4 qubits | 53.71% | 2.73% | 51.04% |
| 8 qubits | 59.34% | 0.37% | 56.50% |

These are the completed baseline multi-seed experiments. Future multi-seed
tests for new improvement variants are currently deferred by the user.

### Classical baselines, three seeds

The classical baselines use the same 384-dimensional input, the same 64-unit
nonlinear compression shape, an 8-dimensional output, and the same 5-way/1-shot
episodic protocol. Each classical baseline trains its own compression network;
the learned compression weights are not shared with the quantum model.

| Model | Mean accuracy | Accuracy standard deviation | Mean weighted F1 |
|---|---:|---:|---:|
| Classical Euclidean ProtoNet | 59.29% | 1.45% | 56.75% |
| Classical cosine ProtoNet | 59.41% | 0.85% | 56.20% |

Interpretation: the current quantum model is competitive, but it has not yet
shown a clear accuracy advantage over simpler classical metric models.

### Longer training and learning-rate sweep

These experiments used 8 qubits, seed 7, and 600 validation episodes:

| Training episodes | Learning rate | Accuracy | Weighted F1 | Runtime |
|---:|---:|---:|---:|---:|
| 2,000 | 0.0003 | 61.48% | 58.50% | 5.9 minutes |
| 2,000 | 0.001 | 61.58% | 58.54% | 6.4 minutes |
| 2,000 | 0.003 | 58.68% | 55.72% | 6.3 minutes |
| 5,000 | 0.001 | 61.74% | 58.95% | 14.0 minutes |

The 5,000-episode run used the best rate from the 2,000-episode sweep. The
gain from 2,000 to 5,000 episodes was small, so simply training longer is not
currently the strongest expected improvement.

## 10. Scientific and implementation guardrails

- Do not claim quantum advantage, speedup, or hardware compatibility.
- Do not describe exact statevector runtime as quantum-hardware runtime.
- Do not move QCHBA into the main trainable architecture without user approval.
- Keep train and validation relations disjoint.
- Keep the same episode list and declared input protocol when comparing models.
- Record seed, qubit count, episode counts, learning rate, and model settings in
  every result.
- Do not change several major factors at once when testing an improvement.
- Treat one-seed improvements as provisional until tested across seeds.
- Preserve the old exploratory implementation and unrelated worktree changes.
- If a future implementation choice is not determined by the specification,
  ask the user before coding it.
